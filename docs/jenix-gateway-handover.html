Jenix Lock Gateway — Handover

Everything you need to take over the Jenix Lock Gateway and build your own software on its HTTP API. The full endpoint reference is in the API & Integration Guide; this note covers what you receive, the first-time setup and the rules that matter most.

Firmware 1.2.14 HTTP/JSON over Wi-Fi (LAN) Bearer token Several locks per gateway

1 · What you receive

  • Jenix Lock Gateway (ESP32-S3), firmware 1.2.14, factory-fresh (LED blinking purple on power-up)
  • 5 V / 2 A USB power adapter — use this or an equivalent; weak chargers cause restarts
  • jenix-gateway-api.html — API & Integration Guide (all endpoints, examples, errors)
  • jenix-lock-user-guide.html — end-user guide for the Jenix Lock app
  • Optional: Jenix Lock app (Android test build) for quick setup and testing

2 · First-time setup (choose one)

A · With the Jenix Lock app

Tap + → Set up new gateway and follow the steps. The app connects the gateway to your Wi-Fi and stores its API token. Read the token later from the gateway's USB console (TOKEN) if your software needs it.

B · From your own software (no app)

  1. Power the gateway; join its open Wi-Fi JenixLock-XXXX. The gateway is at 192.168.4.1.
  2. GET http://192.168.4.1/api/health → "setup": true and the device_id.
  3. POST http://192.168.4.1/api/provision with {"ssid":"<wifi>","pass":"<password>"}. The reply contains your API token — store it securely.
  4. Poll GET /api/provision/status until "state":"connected"; note the new ip.
  5. POST /api/provision/finish (with the token) closes the setup network. Rejoin your Wi-Fi and use http://<ip> from now on.
If the gateway's IP changes later, find it again by probing GET /api/health on the subnet and matching device_id, or via mDNS jenixlock-xxxx.local.

3 · Add a lock

  1. Wake the lock (touch its keypad). GET /api/scan lists nearby locks as Lck1_<ID>. Use the bare ID after the underscore everywhere.
  2. Optional: GET /api/probe?lock=<ID> checks the model; "supported": true is required.
  3. POST /api/bind:
    • New or factory-reset lock: {"lock_id":"<ID>","password":"<6 digits>","tz_minutes":330,"set_password":true} — the gateway sets this connection password on the lock.
    • Lock already set up: the same without set_password, using its existing 6-digit connection password.
  4. Verify: GET /api/version?lock=<ID>. Error login error 19/33 = wrong password (unbind and retry); -1 = lock asleep (wake it, retry).

4 · Rules that matter

TopicRule
Lock IDAlways the bare ID (8F3EE684ECE3), never Lck1_… — it is part of the login key.
Connection password6 digits, used only by the gateway to log in. Not a keypad PIN.
Unlock / lockSend a lock user's ID + that user's keypad PIN. 502 "unlock rejected" = wrong user/PIN.
PINsMust be unique per lock. A refused PIN returns 409 — show users only "choose a different PIN", never the reason (it would reveal another user's PIN).
Temporary door codesGenerated offline from the keypad admin PIN and the lock's local time (its time zone). Algorithm and test vector are in the API guide.
Auto closeThe lock's own delay needs its door magnet; for API/app unlocks use /api/settings/app-autoclose (gateway re-locks, no magnet needed).
BatteryThe gateway measures every lock every 6 h — read GET /api/alerts (low below 25 %).
RecordsMerge the lock's log (PIN, fingerprint, card) with the gateway's log (app, cloud, auto close).

5 · Network & security

  • Plain HTTP on the local network; every endpoint except /api/health needs the bearer token. Keep the token server-side; reset the gateway to rotate it.
  • Wi-Fi repeaters with the same network name may block traffic between their clients and the main router's clients. The gateway joins the strongest access point; /api/health shows which one (wifi_bssid). Prefer one router or a proper mesh system for the gateway's Wi-Fi.
  • Place the gateway within about 5–8 m of the locks. GET /api/signal?lock=… shows the live signal.

6 · Updates, reset & light

  • Firmware updates: from the Jenix Lock app (Gateway settings → Update) or POST /api/ota/upload. Wi-Fi, token and locks are kept; a bad file is rejected. /api/health reports fw_version.
  • Factory reset (gateway only): press RESET 10×, about once per second (white blink per press, amber from the 5th, then purple). Clears Wi-Fi, token and bindings — never the locks' users.
  • Light: purple blink = setup · blue = online · red blink = Wi-Fi lost · 3 red flashes = a command failed · 2 green flashes = unlocked · amber flash = locked.
